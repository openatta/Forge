# 02｜任务与问题生成

> 系列：[总览](00-总览-蒸馏关键环节与学习路线.md)
> 阅读时间：约 15 分钟
> 回答的问题：学生该学什么？问题从哪来、怎么保证覆盖、怎么控制难度和多样性？

---

## 一、为什么问题生成是第一杠杆

蒸馏数据 = 问题 × 教师回答。教师回答的质量有上限（教师能力），但**问题集的覆盖和难度分布没有天然上限约束，完全由你设计**——这就是问题生成是第一杠杆的原因。同样的教师，问题集平庸则学生平庸。

问题生成的三个失败模式，对应三个设计目标：

| 失败模式 | 后果 | 设计目标 |
|---|---|---|
| 覆盖偏斜（生成模型只出它"喜欢"的题） | 学生能力有系统性空洞 | **覆盖受控**：先定义领域结构，配额生成 |
| 难度失配（题太easy或太难） | 训练信号为零或学生学不动 | **难度实测**：以师生实测成功率定难度 |
| 同质化（表面不同实为同一模板） | 训练预算浪费、指标虚高 | **多样性度量**：多层去重 + 分布统计 |

## 二、问题的六个来源（按可信度排序）

1. **真实业务日志**——分布最真，直接反映线上需求。需要脱敏、授权。数量有限但应作为"分布锚点"：合成题的分布应向它对齐，而不是反过来。
2. **领域文档反向出题**——从规章/手册/代码库/知识库中抽取片段，让 LLM 生成"这个片段能回答的问题"（及答案依据）。天然带证据、可验证性好。
3. **专家种子 + 变体扩展**——专家写 50–200 道种子题，LLM 做受控变形（改数字、换实体、加约束、换语言表述）。质量高、可控性强。
4. **公开数据集迁移**——数学/代码/工具调用已有大量公开题库（GSM8K/MATH、LiveCodeBench、BFCL 等）。注意：只能用作训练来源时要做评测去污染。
5. **程序化生成**——用代码模板生成题目和金标准答案（如随机生成 SQL 任务+可执行数据库、随机生成 API 调用场景）。**答案天然正确、难度参数化可控**，是 Agent 任务的主力来源，详见 `03`。
6. **纯 LLM 自由生成**——最便宜也最不可靠，只应在前五种来源的框架内使用（给定知识点、难度、任务形式让它填空），不应让它自由决定"领域里有什么"。

## 三、主流生成方法一览

### 3.1 指令类问题

- **Self-Instruct**：种子任务→LLM 仿写新任务→过滤→滚雪球。开创性但同质化严重，现在只用其框架思想。
- **Evol-Instruct（WizardLM）**：对已有问题做定向进化——加深（加约束/加推理步）、加宽（换主题）。是**难度爬坡**的标准手段：学生掌握 level-k 后，用 Evol 生成 level-k+1。
- **Magpie**：给对齐模型只输入 chat 模板前缀，让它自己"吐出"用户问题。免种子、量大，分布贴近该模型的对齐数据；适合快速铺量，但领域控制力弱。
- **Persona Hub**：用海量人设（"一位怀疑供应商报价的采购经理"）驱动同一知识点生成视角迥异的问题。是**多样性**最有效的放大器，与覆盖矩阵正交组合：`知识点 × 人设 × 任务形式`。
- **指令回译（Instruction Backtranslation）**：从无标注领域语料反推"什么指令会产生这段文本"，适合领域文档多、标注少的场景。

### 3.2 推理类问题

推理蒸馏的问题生成有一个特殊要求：**答案必须可机器验证**（否则后续无法做拒绝采样，见 `04`）。手段：

- 优先选答案为数值/选项/可执行结果的题型；
- 对开放解答题，让教师先生成"题目+参考答案+验证方式"三元组，验证方式不明确的题直接丢弃；
- 从既有可验证题做**受控变体**（改数据、改条件）比从零生成更可靠——变体可以复用原题的验证器。

### 3.3 Agent/工具类任务

Agent 任务生成的单位不是"一句话问题"而是"任务 spec"：

```text
任务 spec = 初始环境状态 + 用户目标 + 可用工具集 + 成功判据（可执行的检查函数）
```

生成策略（详细基础设施见 `03`）：

- **APIGen / APIGen-MT 路线**：从 API/工具定义出发，采样工具组合→生成需要这些工具的任务→用执行验证任务可完成性。多轮版本引入模拟用户。
- **SWE-smith 路线**：对真实代码库程序化注入 bug，生成"修复它"的任务——任务无限量、判据（单测）现成。这个思路可推广到任何"状态可损坏+可检查"的环境（数据库、配置、文档）。
- **反向轨迹法（TOUCAN 等）**：先让强教师在真实环境（如 MCP 工具集）里自由探索产生轨迹，再从成功轨迹反推任务描述。适合工具集庞杂、难以枚举任务的场景。

## 四、覆盖控制：矩阵 + 配额

自由生成的分布永远偏斜，覆盖必须显式管理：

1. 定义一个**小而清晰**的覆盖矩阵：`子领域 × 知识点/工具 × 能力类型 × 难度 × 任务形式`。第一期 2 个维度粒度粗一点没关系，关键是每道题都打上标签；
2. 给每个格子设**配额**（按业务重要性和风险加权），生成和入库按配额执行；
3. 每轮统计：空白格子数、超配格子、每格的模板族数量（防止一个格子里全是同一模板的改写）。

难度不由生成时的主观标签决定，而由**实测**决定：教师和学生各采样 k 次的成功率 `(p_T, p_S)` 才是难度坐标。最有训练价值的区域是 `p_T 高、p_S 低`；`p_T 低` 的题进"换教师/人工"队列；`p_S 高` 的题少量保留做回归。

## 五、去重与去污染

四层去重（逐层加严）：

1. 精确/近似文本去重（MinHash/SimHash）；
2. 语义去重（embedding 聚类，簇内只保留代表 + 控制簇大小上限）;
3. **模板族去重**——最容易漏的一层：把"同一解法结构、只换表面参数"的题归为一族，训练集内限制每族数量；
4. **评测去污染**——训练题与评测题做 n-gram + 语义双重比对，命中即从训练集剔除。模板族必须整族只进训练或只进评测（这是 `06` 对照实验可信的前提）。

## 六、常见坑

1. **让 LLM 自由决定领域内容**——覆盖会向模型先验坍缩，冷门但重要的知识点永远出不来。矩阵先行。
2. **难度用 LLM 标签**——LLM 标的"困难"和学生实测的困难相关性很差，一切以师生实测为准。
3. **合成题分布与线上分布脱节**——保留一个真实日志锚点集，定期比较合成集与它的分布距离（长度、话题、任务形式）。
4. **无验证方式的题混入推理集**——它们会在 `04` 阶段污染拒绝采样，生成时就拦。
5. **产能错觉**——十万道题不等于十万个训练信号；按模板族数、覆盖格子数汇报产能，不按题数。

## 七、进一步学习（小综述）

**方法原典**（按提出顺序，各读 15 分钟即可掌握思想）：
- [Self-Instruct](https://arxiv.org/abs/2212.10560) ——合成指令的框架起点。
- [WizardLM / Evol-Instruct](https://arxiv.org/abs/2304.12244)——难度定向进化，至今仍是难度爬坡的默认方法。
- [Magpie](https://arxiv.org/abs/2406.08464)——自生成问题的极简方案。
- [Persona Hub](https://arxiv.org/abs/2406.20094)——十亿人设驱动多样性，读方法部分。
- [Instruction Backtranslation](https://arxiv.org/abs/2308.06259)——从语料反推指令。

**Agent 任务生成**：
- [APIGen](https://arxiv.org/abs/2406.18518) / [APIGen-MT](https://arxiv.org/abs/2504.03601)——工具调用任务的"生成+执行验证"流水线，xLAM 模型的数据底座。
- [SWE-smith](https://openreview.net/forum?id=63iVrXc8cC)——程序化制造软件工程任务，"损坏+检查"范式的代表。
- [ToolACE](https://arxiv.org/abs/2409.00920)、[TOUCAN](https://arxiv.org/html/2510.01179)——大规模工具数据合成的两种路线（自演化 API 池 / 真实 MCP 环境轨迹反推）。

**工具链**（生成管道的工程载体，选型分析见 `90`）：
- [distilabel](https://github.com/argilla-io/distilabel)（Argilla）——声明式合成数据 pipeline，内置 Self-Instruct/Evol/Magpie 等步骤。
- [Curator](https://github.com/bespokelabsai/curator)（Bespoke Labs）——大批量结构化生成，容错和缓存做得好。
- [synthetic-data-kit](https://github.com/meta-llama/synthetic-data-kit)（Meta）——文档→QA 的轻量工具。
- [NeMo Curator](https://docs.nvidia.com/nemo/curator/latest/curate-text/synthetic/index.html)（NVIDIA）——含去重/质量过滤的全套数据 curation。

**数据集全景**：
- [llm-datasets](https://github.com/mlabonne/llm-datasets)——后训练数据集与工具的持续维护清单，找公开题源先看这里。

## 八、一页结论

```text
问题集决定学生上限：覆盖 × 难度 × 多样性三管齐下
六个来源按可信度排：日志 > 文档反推 > 专家种子 > 公开集 > 程序生成 > 自由生成
Agent 任务生成的是"环境+目标+判据"，不是一句话
覆盖靠矩阵配额，难度靠师生实测，多样性靠人设×模板族控制
四层去重，评测污染零容忍
```
