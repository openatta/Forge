## 一、一个坐标系看清所有算法

蒸馏训练算法看似繁多，其实只由两个轴决定：

```text
轴1：监督信号粒度   序列(文本) → token分布(logits) → 偏好(排序) → 奖励(标量)
轴2：训练数据分布   off-policy(教师/固定数据的序列) → on-policy(学生自己生成的序列)
```

| | off-policy（学教师的序列） | on-policy（在学生序列上学） |
|---|---|---|
| **序列级** | SFT（教师答案微调） | 拒绝采样自训练（学生自己的正确样本） |
| **token 级** | token-KD（前向 KL 拟合教师分布） | **on-policy KD / GKD**（教师给学生的 token 打分） |
| **偏好级** | DPO 及变体 | 在线 DPO / 迭代偏好 |
| **奖励级** | —（离线 RL 少用） | RLVR（GRPO/PPO + 可验证奖励） |

**为什么 on-policy 重要**：SFT 只在教师轨迹上训练，学生推理时沿自己的历史 token 生成，一步走偏就进入训练时从未见过的状态且无法恢复（exposure bias / 复合误差）。on-policy 方法让学生在**自己会犯的错**上得到监督，这是它稳定优于纯 SFT 的机制来源。Thinking Machines 的公开实验给出过一个量级感受：on-policy 蒸馏达到与 RL 相当的推理提升，计算成本低一个数量级左右——因为它有教师逐 token 的密集信号，而 RL 只有序列级稀疏奖励。

## 二、各方法要点速览

### 2.1 SFT（永远的起点）

- 用验证后的教师序列做标准交叉熵。是所有配方的冷启动层，也是唯一"闭源 API 教师就能做"的方法；
- 关键工程细节：observation/环境 token 打 loss mask（`03`）；多轮轨迹按学生模板渲染；packing 提升吞吐但注意跨样本注意力泄漏（用带文档 mask 的 packing）；
- 学习率比预训练低 1–2 个数量级，epoch 通常 2–4，看隔离集早停。

### 2.2 token-KD（白盒、off-policy）

- 最小化 `KL(p_T ‖ p_S)`（前向，mode-covering）或 `KL(p_S ‖ p_T)`（反向，mode-seeking）在教师序列每个位置上；
- 前向 KL 会强迫小学生覆盖教师全部模式（学不动时表现为"平均化"退化）；MiniLLM 提出用反向 KL 让学生集中到教师高概率区；
- 实操默认值：**top-k logits（k=8–20）+ 温度 1–2 + 与 CE 混合（α≈0.5）**，先对比 SFT 是否有增量，没有就砍掉——token-KD 不是必需品，在师生同家族且数据充足时收益常常有限。

### 2.3 偏好优化（DPO 系）

- 用途不是提正确率，而是塑形：格式遵从、简洁性、拒答边界、工具选择偏好；
- 数据来自 `04` 的对比编译（验证通过 vs 失败、高效 vs 绕路），β 典型 0.05–0.3；
- 放在 SFT 之后小剂量使用；大剂量 DPO 容易压低多样性并出现长度 hack。

### 2.4 on-policy KD / GKD

流程：学生生成 → 教师对学生序列逐 token 打分（teacher-forced 前向）→ 学生最小化逐 token 反向 KL → 循环。

- 需要**本地白盒教师**（API 做不了任意序列打分，见 `03`）；且要求师生同 tokenizer（跨家族需 GOLD 类对齐方案）；
- 与 SFT 混合使用（GKD 论文的 λ 参数控制 on-policy 数据占比），纯 on-policy 冷启动会浪费大量教师算力在垃圾序列上——**先 SFT 到能生成基本合格的序列，再上 on-policy**；
- 这是当前推理蒸馏性价比最高的第二阶段：Qwen3 等多个 2025–2026 年的公开模型确认在用。

### 2.5 RLVR（可验证奖励的 RL）

- GRPO/PPO + 执行验证器给奖励，不需要教师参与训练循环（教师的作用退到冷启动数据）；
- 上限最高（学生可以探索出超越教师的策略），成本与工程复杂度也最高：奖励 hack、训练不稳定、需要 `03` 的环境以在线吞吐运行；
- 决策依据：**学生 pass@k 显著高于 pass@1 时**（能力在里面、采不出来），RL/on-policy 收益大；pass@k 也低时说明能力缺失，先回去补 SFT 数据。

## 三、推荐配方（按阶段递进）

```text
阶段0  底座直接评测 → 建立基线和 pass@k 画像
阶段1  验证后教师数据 SFT → 这是性价比最高的 80%
阶段2  +小剂量 DPO（格式/边界塑形）
阶段3  +on-policy KD（本地教师，修复自生成错误）
阶段4  +RLVR（只在 pass@k 缺口大、验证器可靠时）
每一阶段的准入条件：上一阶段在固定预算对照中已经收敛
```

多数项目做到阶段 2 就能拿走大部分收益；阶段 3/4 属于"从 85 分到 92 分"的投入。

## 四、训练工程要点（多卡服务器场景）

- **框架**：TRL（SFT/DPO/GKD 全有，生态最好）、LLaMA-Factory（配置化全家桶，上手最快）、verl（RL 和 on-policy 蒸馏的生产级实现，教师放独立 GPU 池）、NeMo-RL（NVIDIA 栈）。选型分析见 `90`；
- **LoRA vs 全参**：8B 以下全参优先（多卡服务器扛得住，效果稳定）；LoRA 用于快速探针实验（`01` 的教师选型、`04` 的数据信号消融）——迭代速度比终版效果重要的场合；
- **超参搜索预算要公平**：对照实验里每个方法给相同的搜索预算，否则比的是调参运气；
- **checkpoint 策略**：按隔离集指标存 best + last，所有 checkpoint 关联数据批次 ID（`06` 归因用）。

## 五、常见坑

1. **把合成数据 SFT 叫"蒸馏"就完事**——SFT 是起点没错，但不解决 exposure bias；学生"会背不会走"时应上 on-policy，而不是无脑加数据。
2. **token-KD 迷信**——同家族+大数据时增益常可忽略，先消融再投入。
3. **DPO 修正确率**——DPO 对事实性/正确率的提升微弱且易 hack，正确率问题回到数据和 SFT/RL 解决。
4. **on-policy 阶段丢掉离线锚点**——纯追学生当前错误分布会遗忘基础能力，保留 20–50% 离线数据混训。
5. **RL 前不查验证器漏洞**——奖励 hack 的第一来源是验证器写得松（如代码任务只测样例不测边界），RL 会精准找到所有漏洞。
6. **用训练 loss 判断收敛**——蒸馏各阶段的 loss 与下游能力相关性弱，一切以隔离评测为准（`06`）。

## 六、进一步学习（小综述）

**必读三篇（方法主线）**：
- [MiniLLM](https://arxiv.org/abs/2306.08543)——反向 KL 用于生成式蒸馏的动机与推导。
- [GKD: On-Policy Distillation of Language Models](https://arxiv.org/abs/2306.13649)——on-policy KD 的奠基论文，λ 混合设计。
- [Thinking Machines: On-Policy Distillation](https://thinkingmachines.ai/blog/on-policy-distillation/)（2025 博客）——把 on-policy KD 讲得最清楚的工程读物，含与 RL 的成本对比实验。

**综述与教程**：
- [Knowledge Distillation for Language Models 教程](https://aclanthology.org/2025.naacl-tutorial.4/)（NAACL 2025）——算法全景图，适合建立分类框架。
- [awesome-on-policy-distillation](https://github.com/chrisliu298/awesome-on-policy-distillation)——OPD 论文/框架/工业报告的持续维护清单，追新看这里。

**偏好与 RL**：
- [DPO](https://arxiv.org/abs/2305.18290)——直接偏好优化原文。
- [DeepSeekMath / GRPO](https://arxiv.org/abs/2402.03300)——RLVR 的主流算法出处。
- [DeepSeek-R1](https://arxiv.org/abs/2501.12948)——"RL 训教师、SFT 蒸学生"的完整公开配方；其结论"小模型直接 RL 不如蒸馏"值得反复读。

**框架文档**：
- [TRL GKDTrainer](https://huggingface.co/docs/trl/gkd_trainer)、[verl OPD 文档](https://verl.readthedocs.io/en/latest/algo/opd.html)（支持 GKD 式 top-k 前向 KL 与 PG 式反向 KL、教师独立 GPU 池、多教师路由）、[NeMo-RL distillation](https://docs.nvidia.com/nemo/rl/latest/)。

## 七、一页结论

```text
两轴定位一切算法：信号粒度 × on/off-policy
配方递进：SFT → 小剂量DPO → on-policy KD → RLVR，每级有准入条件
on-policy 的价值 = 修复 exposure bias，用教师密集信号拿到接近 RL 的收益
pass@k 画像决定该补数据还是该上 RL
所有结论以固定预算对照 + 隔离评测为准
```
