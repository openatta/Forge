# 04｜数据验证、过滤与选择

> 系列：[总览](00-总览-蒸馏关键环节与学习路线.md)
> 阅读时间：约 12 分钟
> 回答的问题：教师产出中哪些配进训练集？怎么验证正确性、怎么按价值排序、选多少？

---

## 一、位置与心法

`03` 产出的是"原料"：每题 k 个教师候选 + 轨迹 + 执行结果。本环节把原料变成训练集，心法一句话：

> **验证是硬门槛，选择是软排序；先用门槛把错的挡住，再用排序把预算花在刀刃上。**

蒸馏数据的第一性风险是**教师错误传播**——学生会忠实地学会教师的错误，而且比学会正确知识更难逆转（错误往往更"简单"）。所以验证层的召回率直接决定学生天花板。

## 二、验证：五级流水线

按可信度从高到低、成本从低到高依次过滤（能被上级判掉的不进下级）：

| 级别 | 手段 | 适用 | 备注 |
|---|---|---|---|
| L1 执行验证 | 单测、SQL 执行、环境终态检查、数学答案检查器 | 代码/数学/Agent | 金标准；数学用 math-verify 类工具而非字符串比对（等价表达式问题） |
| L2 规则/Schema | 格式校验、JSON schema、业务规则、单位/范围检查 | 结构化输出、工具参数 | 便宜，先跑 |
| L3 证据核对 | 答案引用与源文档比对（NLI/字符串定位） | 文档问答、RAG 蒸馏 | 引用不存在=直接毙 |
| L4 LLM Judge | 分项 rubric 打分，非"总体好不好" | 开放式回答 | 必须校准（见 2.2） |
| L5 人工抽检 | 专家按分层抽样审核 | 全部 | 校准 L1–L4，估计流水线整体误放率 |

### 2.1 拒绝采样（rejection sampling）是核心操作

推理蒸馏的标准做法：每题 k 个教师样本 → 验证器过滤 → 从通过者中选 1–2 条最优进训练集。这同时完成三件事：剔除错误答案、估计题目难度（通过率）、提供偏好对的原料（通过 vs 未通过）。DeepSeek-R1、OpenThoughts 等公开配方的数据主体都来自这一操作。

对**过程**的额外检查（推理/轨迹数据）：

- 答案对但过程错（碰巧答对）：抽查中间结论是否支撑下一步；简单实用的代理指标——把最终答案遮住，让另一模型只看过程推答案，推不出的过程可疑；
- 轨迹的无效步剪除：删掉不影响终态的绕路步骤前后各做一次重放确认（`03`）；
- **有价值的失败-恢复段落要保留**：错误→发现→修正是独立能力，与"无意义反复失败"区分开。

### 2.2 LLM Judge 的校准纪律

Judge 只在 L1–L3 不可用时上场，且必须：分项 rubric（事实性/完整性/格式分开打）、隐藏模型身份、随机交换候选顺序、用 100–200 条人工标注样本测 Judge 与人的一致性（Cohen's κ 至少 >0.6 才可用）、监控长度偏好。**未校准的 Judge 分数不允许作为过滤依据**，只能做参考特征。

## 三、过滤：从个体到集合

个体过滤（单条数据自身的合格线）之后，还有集合层面的操作：

1. **去重**：与 `02` 的四层去重同一套机制，在"编译进训练集"时再执行一次（教师回答也可能高度重复）；
2. **配额约束**：覆盖矩阵每格的最终入选量对齐配额，防止价值分选择把预算全砸进某一格；
3. **长度与格式健康度**：截断样本、超长离群、模板噪声（教师的口头禅开场白）统一清理；教师文风的"水词"可以做轻量改写压缩——训练 token 是钱。

## 四、选择：价值排序

候选远多于预算时才需要精细选择。可用的价值信号（按实证有效性排序）：

1. **师生差距**：`max(0, p_T − p_S)`，教师稳定会而学生不会的题信号最强；p_S 用当前学生多采样实测；
2. **覆盖边际贡献**：填补空白格子 > 加强薄弱格子 > 堆积饱和格子；
3. **学生可学习性**：学生对该样本的 NLL 适中（太低=已会，太高=学不动）；或给提示后学生能做对（提示可解性）；
4. **教师稳定性**：k 采样通过率高的答案更可信；
5. **多样性**：同簇样本边际收益递减，簇内限额。

两条纪律：

- **信号先验证再上线**：每个信号单独做小规模消融（用它选的 vs 分层随机），赢了才纳入综合分。经验上师生差距和覆盖配额最稳，NLL 类信号噪声大；
- **"少而精"有实证支持但有边界**：LIMA/LIMO/s1 系列证明千级精选样本能激发强底座的推理能力——前提是底座预训练里已有该能力、只需"引出"。领域知识本身缺失时，少量样本引不出不存在的东西，仍需足量覆盖。判断方法：先用 1k 精选试探，增益饱和快说明是"引出型"任务，数据量可以小。

## 五、编译：从合格数据到训练格式

最后一步把合格样本编译成 `05` 需要的格式：

| 原料 | 编译产物 |
|---|---|
| 验证通过的最优教师答案/轨迹 | SFT 样本（学生模板渲染，observation 打 mask） |
| 同题"通过 vs 未通过"、"高效 vs 绕路" | DPO/偏好对（注意控制混杂：不要让 chosen 同时更长更漂亮） |
| 教师 top-k logprobs（与学生 token 对齐后） | token-KD 样本 |
| 学生失败点 + 教师续写纠正 | 纠错样本（on-policy 原料） |
| 高质量题目本身（不含答案） | RL/on-policy 训练的 prompt 集 |

每条编译产物保留指回轨迹 ID 和验证记录的引用——`06` 做归因时要用。

## 六、常见坑

1. **用教师置信度当验证**——教师对错误答案同样自信，置信度只能做参考特征。
2. **Judge 分数直接过滤**——未校准的 Judge 会系统性偏向某种文风，学生学到的是文风不是能力。
3. **偏好对里混杂变量失控**——chosen 比 rejected 长 3 倍且格式更好，DPO 学到的就是"写长点"。
4. **过滤后不看分布**——高强度过滤会悄悄改变覆盖分布（难题被筛掉更多），过滤后必须重新对照配额。
5. **训练集只有成功轨迹**——学生学不会说"做不到"，适量保留"诚实失败"样本（正确识别任务不可行）。

## 七、进一步学习（小综述）

**拒绝采样与数据配方**：
- [DeepSeek-R1](https://arxiv.org/abs/2501.12948) 第 2.3 节——拒绝采样 + 规则奖励的工业级配方。
- [OpenThoughts](https://arxiv.org/abs/2506.04178)——系统消融了推理数据管线的每个环节（问题源、过滤、教师选择），"哪些过滤真的有用"目前最全面的实证。

**"少而精"路线**：
- [LIMA](https://arxiv.org/abs/2305.11206)、[LIMO](https://arxiv.org/abs/2502.03387)、[s1](https://arxiv.org/abs/2501.19393)——千级样本激发能力的三个里程碑，注意它们的共同前提（强底座+引出型任务）。

**过程验证**：
- [Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)（OpenAI）——过程监督 vs 结果监督的奠基实验；过程奖励模型（PRM）的出发点。
- [Distilling Step-by-Step](https://aclanthology.org/2023.findings-acl.507/)——教师解释作为监督信号的开端。

**Judge 校准**：
- [Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)（MT-Bench 论文）——Judge 偏差（位置、长度、自恋）的系统刻画，校准清单的来源。

**工具**：
- [math-verify](https://github.com/huggingface/math-verify)——数学答案等价性检查的标准库。
- [datasketch](https://github.com/ekzhu/datasketch)（MinHash）、[text-dedup](https://github.com/ChenghaoMou/text-dedup)——去重工具箱。

## 八、一页结论

```text
验证五级流水线：执行 > 规则 > 证据 > 校准Judge > 人工抽检
拒绝采样（k采样+验证器过滤）是蒸馏数据生产的核心操作
选择信号逐个消融验证，师生差距 + 覆盖配额最稳
偏好对严控混杂变量；过滤后重查覆盖分布
每条训练样本可追溯到轨迹与验证记录
```
