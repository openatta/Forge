## 一、蒸馏评测的特殊性

蒸馏评测比普通模型评测多三个对象和一个闭环：

```text
对比对象：教师（上界） vs 旧学生（基线） vs 新学生（产物） vs 消融组（归因）
闭环：评测结果 → 错误归因 → 生成针对性数据（回到02） → 再训练 → 回归检查
```

一次性评测回答"这版模型多好"；蒸馏评测要回答的是"**差距还剩在哪、下一轮补什么**"。这决定了评测集必须按能力单元结构化（能定位），而不只是一个总分（只能排名）。

## 二、评测集体系

| 集合 | 用途 | 纪律 |
|---|---|---|
| 开发集 | 训练中选超参、早停 | 可以反复看 |
| 隔离测试集 | 版本间正式对比 | 与训练集按模板族/文档/时间隔离（`02`）；每轮只看一次汇总 |
| 隐藏审计集 | 防止对隔离集过拟合 | 少数人持有，里程碑才跑 |
| 通用回归集 | 检测通用能力/安全退化 | 训练前固定，设最大允许降幅 |
| 真实回放集 | 分布对齐检查 | 按时间滚动更新 |

**隔离的单位是"模板族"而非"题目"**：同一解法结构的变体必须整族同侧，否则测的是记忆不是泛化。这在 `02` 生成阶段就要打好族标签。

### 能力单元报告格式

总分之外，按覆盖矩阵（`02`）的格子出报告：

```text
每格：成功率 + 样本数 + 95%置信区间 + 相对上轮变化
汇总：宏平均（格子等权） + 最差k个格子 + 高风险格子单列
```

宏平均防止大格子淹没小格子；最差格子防止"平均提升掩盖局部崩坏"。

## 三、对比实验设计

### 3.1 固定预算原则

所有方法对比必须固定：训练 token 数（不是样本数——轨迹长度差异巨大）、超参搜索预算、推理配置（温度、最大长度、工具预算）。报告多种子均值±方差（至少 3 个 seed，小模型训练方差不小）。

### 3.2 标准对比组

一轮蒸馏至少跑这几组，否则无法归因：

| 组 | 回答的问题 |
|---|---|
| 底座（未训练） | 起点在哪 |
| 分层随机数据 SFT | 你的数据选择是否有超越随机的价值 |
| 本方案 | 主结果 |
| 教师 | 还剩多少差距（质量保持率 = 学生/教师） |
| （第二轮起）上轮学生 | 增量收益、回归检测 |

### 3.3 Agent/推理任务的评测细节

- **pass@1 和 pass@k 都报**：pass@1 是交付指标，pass@k 是能力储备指标（差距大→上 on-policy/RL，见 `05`）；
- Agent 任务用 `03` 的环境跑**终态验证**，同一环境版本、同一 harness、同一预算；每任务跑 ≥4 次报均值（环境和采样都有方差）；
- 除成功率外记录：步数、token 消耗、无效调用率、格式废品率——学生常见"成功率追平但步数翻倍"，这在部署上是失败；
- **异常切片单独测**：工具报错/空结果、干扰信息、不需要工具的题（防工具滥用）、应当拒绝的任务（防越权）。

## 四、错误归因：从分数到诊断

评测的产出不是分数而是**错误分类账**。实用的错误分类法（Agent/推理场景）：

```text
知识缺失     不知道领域事实/规则        → 补知识型SFT数据（02：文档反推题）
分解错误     计划就错了                → 补规划轨迹、过程监督
工具选择错误  该用A却用B               → 补工具对比偏好对
参数错误     工具对但参数错            → 补参数校验数据+格式约束
状态跟踪丢失  多步后忘记之前的结果      → 补长轨迹数据；检查上下文长度
不恢复       一步失败后崩掉            → 补失败-恢复轨迹（03专门生产）
幻觉执行     声称做了没做的操作        → observation mask检查+终态验证数据
过度拒答     无害任务拒绝              → 补安全近邻正样本
格式退化     JSON/模板错误             → 小剂量DPO+结构化解码兜底
```

归因流程：失败样本抽样 → 人工+LLM 辅助打错误标签 → 按标签×能力格子交叉统计 → 得到"下一轮数据订单"。**这张订单就是 `02` 的输入**，闭环由此形成。

两个有用的自动化信号：

- **first-error-step 分布**：轨迹在第几步开始偏离（用教师或验证器定位），早偏离→规划问题，晚偏离→执行/恢复问题；
- **师生分歧点分析**：同一前缀下教师和学生下一步动作不同的位置，聚类后就是"值得教的决策点"，直接变成 on-policy 纠错数据（`05`）。

## 五、迭代节奏与停止条件

每轮迭代的标准循环（一轮 1–2 周是健康节奏）：

```text
评测诊断 → 数据订单 → 生产+验证 → 训练 → 隔离评测 + 回归
→ 判定：继续 / 换方法 / 停止
```

判定规则建议事先写死：

- **继续**：目标格子提升 ≥ 预设最小值，回归在预算内；
- **换方法**：连续两轮同类数据增益 < 阈值 → 数据边际收益耗尽，换训练方法（`05` 的阶段递进）或换问题生成策略；
- **停止**：质量保持率达标（如达到教师的 90%）或剩余差距集中在"学生容量外"的格子（加数据不涨、pass@k 也低、换更大学生才有解）。

**警惕"评测集驯化"**：每轮都对着同一个隔离集优化，几轮后就过拟合了它。对策：隐藏审计集定期校验 + 隔离集按时间滚动扩充（新模板族只进新版本）。

## 六、常见坑

1. **只报平均分**——蒸馏最常见的失败是局部崩坏，最差格子和高风险格子必须单列。
2. **样本数不够就下结论**——每格 <50 题时置信区间宽得惊人，先算功效再扩格子题量。
3. **训练评测环境不一致**——harness/模板/工具版本任何一个漂移都会造成幽灵退化，全部哈希对账（`03`）。
4. **拿公开榜单当主指标**——污染风险 + 分布错位；公开榜单只做外部参照，主指标永远是自建隔离集。
5. **没有回归预算的概念**——事先约定"通用集最多降 x 点"，超了就回退，而不是事后争论。
6. **评测结果不落数据订单**——评测报告的最后一节必须是"下一轮数据清单"，否则闭环断裂。

## 七、进一步学习（小综述）

**评测框架**：
- [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)——通用基准的标准执行器，回归集的现成载体。
- [Inspect](https://github.com/UKGovernmentBEIS/inspect_ai)（UK AISI）——评测即代码的框架，自建领域评测集的好骨架，支持 Agent 任务和沙盒。
- [lighteval](https://github.com/huggingface/lighteval)（HF）——与 open-r1 管线配套的评测器。

**Agent/工具评测**：
- [BFCL（Berkeley Function-Calling Leaderboard）](https://gorilla.cs.berkeley.edu/leaderboard.html)——工具调用的事实标准基准，其评测代码可复用为自建工具评测的模板。
- [tau-bench / tau2-bench](https://github.com/sierra-research/tau-bench)——多轮+模拟用户场景的评测范式，pass^k（k 次全过）指标值得借鉴——衡量**稳定性**而非运气。

**污染与可信评测**：
- [Data Contamination 综述](https://arxiv.org/abs/2406.04244)——污染检测方法一览；自建集的隔离纪律比检测更根本。

**错误分析方法**：
- [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals) 与 OpenAI/各家 eng blog 的 agent eval 实践文——工程视角的错误分类与切片评测；配合本篇的错误分类账使用。

## 八、一页结论

```text
蒸馏评测 = 结构化诊断，不是排行榜
隔离单位是模板族；报告单位是能力格子（宏平均+最差格+置信区间）
固定预算、多种子、五组对照（底座/随机/本方案/教师/上轮）
pass@1 交付、pass@k 定方法；Agent 任务终态验证+效率指标
错误分类账 → 数据订单 → 回到02，这条回边是系统的心脏
事先写死继续/换方法/停止的判定规则
```
