# 07｜部署、安全与持续蒸馏

> 系列：[总览](00-总览-蒸馏关键环节与学习路线.md)
> 阅读时间：约 12 分钟
> 回答的问题：训好的学生怎么上线？安全属性会怎么变？领域变化后怎么继续学而不遗忘？

---

## 一、从 checkpoint 到部署工件

浮点 checkpoint 不是交付物，**部署工件**（量化+编译+服务配置后的东西）才是。链条：

```text
蒸馏 checkpoint → 量化(AWQ/GPTQ/FP8) → 服务引擎(vLLM/SGLang/TensorRT-LLM)
→ 真实流量配置(并发/上下文/工具) → 这个组合体才是要验收的对象
```

两条铁律：

1. **每个部署工件重跑核心评测**。量化会移动低概率 token 的排序，最常见的退化恰好在蒸馏最关心的地方：工具 JSON 格式、长轨迹稳定性、数学精度、拒答边界。W8A8/FP8 通常安全，W4 必须全量回归；
2. **系统指标按"成功任务"归一**。学生单价便宜但失败率高时，重试+升级成本会吃掉名义节省。核心指标是**每千次成功任务的端到端成本**和 P95 延迟，不是每 token 单价。

### 路由与级联

学生不必覆盖教师全部能力，"学生 + 置信升级"往往是最优部署形态：

```text
学生高置信 → 学生答
学生低置信 / 验证失败 / 高风险类 → 升级教师或人工
```

升级信号从易到难：任务类型规则 → 学生自报不确定（要专门训练，见下）→ 轻量验证器打分。上线时同时监控升级率（成本）与漏升级率（质量），这俩此消彼长，阈值是业务决策。

## 二、安全：蒸馏会移动安全边界

学生不会自动继承教师的安全对齐——能力蒸馏的数据分布里安全样本占比极低，训练会**稀释**底座原有的对齐。三类典型退化：

- 领域数据训多了，安全拒答边界松动（越狱成功率上升）；
- 反向问题：安全数据配比不当 → 无害请求误拒率上升；
- Agent 特有：学会"完成任务优先"后，对危险工具调用的谨慎性下降。

对策清单：

1. 训练配比里**固定保留安全样本配额**（危险题拒绝 + 无害近邻题正常回答，成对出现）；
2. 每轮回归必测安全集（攻击成功率 + 误拒率同报，只报一个没有意义）；
3. Agent 的高危动作**不靠模型自觉**：权限系统、工具白名单、确认门槛在 harness/平台层硬约束；
4. 记住蒸馏数据是攻击面：教师输出可能内嵌它的系统提示泄漏、偏见、过期知识，`04` 的验证层要包含安全过滤。

### 合规红线（立项时就要过）

- 教师 API 的服务条款是否允许输出用于训练（部分厂商明令禁止训练竞品模型）；
- 训练数据中的用户日志是否授权、脱敏；
- 蒸馏产物的许可证链条（底座许可 × 数据许可 × 教师条款的交集）。

## 三、持续蒸馏：领域会漂移，学生要跟上

上线不是终点：领域规则更新、工具接口变更、新业务接入、底座换代，都要求继续训练。持续蒸馏的核心矛盾是**新能力 vs 灾难性遗忘**。

### 3.1 触发机制

不搞定期全量重训，用**事件驱动**：

```text
线上失败率异常（按能力格子监控） → 补题订单（06 的机制延伸到线上）
领域规则/工具变更 → 定向新数据 + 旧数据失效标记（03 的重放判定）
底座升级 → 全量重蒸（老数据可复用，见下）
```

### 3.2 防遗忘的工程手段（按性价比排序）

1. **回放混训**：新数据 + 20–50% 旧能力代表样本（按能力格子分层抽，覆盖旧边界而不只是旧简单题）；
2. **锚定正则**：对基线模型的 KL 约束（等价于把旧模型当第二教师）；
3. **LoRA 增量 + 路由**：新领域走新 adapter，旧能力物理隔离——适合领域间界限清晰的场景；
4. **双模型灰度**：新学生先只接新流量，旧学生兜底，稳定后合流。

### 3.3 资产复用

持续蒸馏的成本优势来自资产复用，前提是 `02`–`04` 的基础设施做对了：

- **问题库和环境**长期有效（任务 spec 与模型无关）；
- **验证器**长期有效（这是回报率最高的资产）；
- 教师轨迹在教师升级后**部分**有效（重放验证决定去留）；
- 训练数据在学生底座换代后基本可以直接复用（重新编译模板即可）。

所以：把预算优先砸向问题库、环境、验证器这三样"跨版本资产"，而不是某一版模型的调参。

## 四、上线决策表

事先写死，避免训完再吵：

| 维度 | 门槛类型 |
|---|---|
| 目标能力 | 主指标 ≥ 预设值；最差格子 ≥ 业务底线 |
| 回归 | 通用集降幅 ≤ 预算；已上线能力零严重回归 |
| 安全 | 严重违规=一票否决；误拒率 ≤ 预算 |
| 系统 | 目标硬件 P95/吞吐/显存达标（用部署工件测） |
| 经济 | 预测流量下每千次成功任务成本 < 现方案 |
| 可运营 | 版本可回滚、失败可归因（数据/模型/教师版本链完整） |

灰度顺序：影子流量（不影响用户）→ 低风险场景小流量 → A/B → 扩量 → 高风险能力最后放开。

## 五、常见坑

1. **只验收浮点模型**——上线的是量化工件，退化就藏在量化里。
2. **安全评测只测攻击不测误拒**——把"变得胆小"误报为"变得安全"。
3. **持续训练每次从最新 checkpoint 续训**——误差累积且无法归因；每轮从固定底座+全量数据重训（数据是资产，checkpoint 不是），除非成本确实不允许。
4. **监控只看平均质量**——线上退化几乎总是从某个能力格子开始，分格监控。
5. **没有回滚演练**——模型回滚要连带 prompt/工具配置一起回滚，上线前演练一次。

## 六、进一步学习（小综述）

- [Distillation Scaling Laws](https://arxiv.org/abs/2502.08606)——部署经济性的理论框架（何时蒸馏划算）。
- [Scaling Down, Serving Fast](https://aclanthology.org/2025.emnlp-industry.119/)（EMNLP 2025 Industry）——蒸馏+剪枝+量化组合上线的工业实录。
- Minitron 系列（[Compact Language Models via Pruning and Knowledge Distillation](https://arxiv.org/abs/2407.14679)，NVIDIA）——"剪枝得到学生结构，再蒸馏恢复能力"的代表路线。
- [Safety Evaluation of DeepSeek Models in Chinese Contexts](https://arxiv.org/abs/2503.16529)——推理蒸馏模型安全边界变化的实证，中文场景。
- [模型量化对能力影响的实证研究（如 How Does Quantization Affect Reasoning](https://arxiv.org/abs/2504.04823)）——量化×推理能力的退化模式。
- 各推理引擎部署文档：[vLLM production](https://docs.vllm.ai/)、[SGLang](https://docs.sglang.ai/)、[TensorRT-LLM](https://nvidia.github.io/TensorRT-LLM/)。

## 七、一页结论

```text
验收对象是部署工件不是 checkpoint；量化后全量回归
指标按成功任务归一：每千次成功任务成本 + P95
学生+置信升级的级联常优于单模型
安全配额进训练配比；攻击率与误拒率同报；高危动作平台层硬约束
持续蒸馏：事件驱动补题 + 回放混训防遗忘 + 从固定底座重训
长期资产 = 问题库 + 环境 + 验证器，预算优先投这三样
```
